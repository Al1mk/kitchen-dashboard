# بسته نهایی بخش رضا — LCC Campus Board (HCI)

این بسته، بخش اختصاصی رضا را برای پروژه گروهی HCI آماده می‌کند: **Newcomer Guide + بررسی نمایشگر فیزیکی + مستندات و Booklet فردی**.

## فایل‌ها

- `prototype/index.html` — پروتوتایپ مستقل و قابل‌کلیک دوزبانه (آلمانی/انگلیسی). بدون Node.js هم با باز کردن فایل در مرورگر اجرا می‌شود. تمام اطلاعات نمونه با برچسب DEMO مشخص شده‌اند.
- `src/app/newcomers/page.tsx` و `src/lib/newcomers/content.ts` — نسخه پیشنهادی برای ادغام با Next.js گروه.
- `docs/hci/booklet/04-reza.md` — منبع Markdown گزارش فردی آلمانی.
- `docs/hci/booklet/04-reza-booklet.docx` و `04-reza-booklet.pdf` — نسخه‌های صفحه‌آرایی‌شده پنج‌صفحه‌ای.
- `docs/hci/research/screen-specs.md` — فرم ثبت مشخصات واقعی نمایشگر.
- `docs/hci/research/interview-guide.md` — پرسش‌های کوتاه برای گفت‌وگو با دانشجویان (هنوز نتیجه مصاحبه‌ای ثبت نشده).
- `docs/hci/design/reza/` — دو Sketch و دلیل انتخاب طراحی.
- `docs/hci/testing/reza-test-plan.md` و `reza-test-record-template.md` — طرح آزمون و فرم ثبت نتیجه واقعی.
- `team-coordination/ALI_message_de.md` — پیام آماده آلمانی برای دریافت تأیید از علی.
- `team-coordination/team-status.md` — مواردی که هنوز به تأیید اعضای گروه یا شواهد واقعی نیاز دارند.

## پیش‌نمایش بدون نصب Node.js

در Finder پوشه `prototype` را باز کن و روی `index.html` دوبار کلیک کن. زبان را با DE/EN عوض کن و هر کارت را باز کن. این پروتوتایپ مسیرها را داخل خودش شبیه‌سازی می‌کند تا مفهوم تعامل قابل نمایش باشد؛ اتصال به نقشه و داده‌های واقعی هنوز انجام نشده.

## ادغام با مخزن اصلی

مخزن تیم: `https://github.com/Al1mk/kitchen-dashboard`

1. ابتدا جدیدترین `main` و `docs/contracts.md` واقعی را بخوان.
2. با علی N1 و تغییر منوی مشترک را هماهنگ کن.
3. فایل‌های داخل `src/` را در مسیر هم‌نام مخزن کپی کن.
4. تغییر ناوبری را تنها پس از review علی اعمال کن؛ این بسته به عمد فایل‌های مشترک را کورکورانه بازنویسی نمی‌کند.
5. مسیر `/map` فقط پس از ادغام واقعی کارت آریان و تأیید قرارداد اضافه شود.
6. اسکریپت‌های واقعی `package.json` را بررسی و تست‌ها را اجرا کن. هیچ تستی پیشاپیش Pass اعلام نشده.

## مواردی که عمداً ساخته یا جعل نشده‌اند

- اندازه/رزولوشن واقعی نمایشگر؛ باید در محل اندازه‌گیری یا از مسئول دستگاه تأیید شود.
- شماره اتاق، طبقه، تلفن، ساعات اداری یا تماس رسمی.
- نتیجه مصاحبه یا usability test؛ باید با داوطلب واقعی انجام شود.
- تأیید علی/اعضای تیم؛ پیام هماهنگی آماده است اما موافقت واقعی ثبت نشده.
- ادغام در GitHub یا Push؛ این بسته فقط فایل قابل دانلود است و دسترسی به حساب/مخزن برای Push ندارد.

## وضعیت در زمان تولید بسته

- پروتوتایپ HTML: فایل ساخته شده؛ تعاملی بودنش از روی کد بررسی شده، اما استفاده واقعی توسط دانشجو هنوز تست نشده.
- Next.js route: فایل ادغام پیشنهادی است؛ به دلیل نبود دسترسی به working tree مخزن اصلی در این محیط، build یا test آن اجرا نشده.
- Booklet: پیش‌نویس پنج صفحه‌ای با وضعیت‌های شفاف و جاهای «NOCH ZU ERHEBEN» است؛ بعد از بررسی دستگاه و انجام تست واقعی باید تکمیل شود.
